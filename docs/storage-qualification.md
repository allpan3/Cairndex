## Storage limits

Portable metadata uses complete temporary files and exclusive hard-link publication.
Source operations also require atomic no-replace relocation. The older direct-SMB
source-copy adapter does not supply either contract to the portable workflow.
NAS-hosted serving is a separate deployment; it does not fix mounted-SMB access.

Mounted-SMB support requires an implementation and review of authenticated,
conflict-safe metadata publication and file/directory no-replace relocation,
including mounted/direct identity checks, disconnect recovery and packaged
credential behavior. Reuse of the existing direct-SMB dependency is an option;
a check-then-rename fallback is not. Until that work passes, keep the current
refusal. Removing mounted-SMB from the product requirements needs an owner decision.

The iCloud generation refusal is consistent with a ctime change; this run does
not identify the actor that changed it. Do not weaken the generation check to
make the test pass. Retained intent and independent versions permit inspection
and a new explicit review. Placeholder hydration/eviction and remote conflict
filenames have no current evidence.

Source reviews retain limits of 128 entries and catalog identities per tree,
4,096 metadata units, bounded receipt bytes and a per-operation storage budget.
There is no automatic purge. External in-place writes and final directory rename
races remain limits. Process termination and injected storage errors do not prove
power-loss safety or provider durability.

## Repeatable container checks

Use an isolated compose project, unused loopback ports, a fresh synthetic library
mount and separate private volumes. Do not reuse an owner data directory. Build
from a source-only context after privacy inspection. `build-and-check.sh` resolves
the development image names from the selected compose project.

Run `infra/docker/smoke.sh IMAGE` and
`infra/docker/backup-restore-smoke.sh IMAGE`. The first reads the selected file's
source generation before requesting playback. The second verifies and activates
a separate private recovery without overwriting its original store.

For the joined workflow, run `infra/docker/portable_smoke.py --url URL --root ROOT
--receipt RECEIPT` against the fresh compose service. `ROOT` is the host path of
its disposable `/libraries/main` mount. After a clean container restart, use the
same arguments with `--phase restart`. After killing only that test process and
starting it again, use `--phase abrupt-exit`. Both phases check protection, source
receipts, restored bytes and the received private draft. The harness never stops
containers itself and does not accept an existing populated root for its initial
phase.
